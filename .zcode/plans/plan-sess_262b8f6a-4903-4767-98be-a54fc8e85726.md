## 修复计划：结果滚动条 + 信息丰富度 + 输入框阻塞 + 测速失效

### 问题诊断

**问题 1：结果页无滚动条**
- `ResultTable` 的 `ListView.builder` 在 `ConstrainedBox(maxHeight: 60%)` 内，但没有 `Scrollbar` 包裹。

**问题 2：结果信息太少**
- 结果表只有 4 列（节点/延迟/国家/来源），但 `LatencyFilter.run` 输出的 JSON 旁文件包含 `jitter_ms` 等丰富数据，目前未被加载。

**问题 3：扫描页输入框输入受阻**
- `scanner_tab.dart:815` 的 `_inputField` 每次 `build()` 都创建新 `TextEditingController`，用户输入一个字符 → `onChanged` → `setState` → 重建 → 新 controller → 光标重置到开头。输入体验极差。

**问题 4：测速完全不工作**
- `speed_test.dart:57` 的 `requestUrl` 用的是源站域名（如 `speed.cloudflare.com`），而不是 CF IP。请求通过 DNS 解析到源站，完全绕过了 CF 代理。正确做法是 URL 用 `$ip:$port`，`Host` 头设为源站域名。
- 同时 `_Semaphore` 没有 `cancel()` 方法，取消测速时信号量仍阻塞。

---

### 修复步骤

#### 1. 修复扫描页输入框（scanner_tab.dart）
- 将 `_delayThreshold`、`_speedThreshold` 等阈值字段改为使用持久化的 `TextEditingController`（在 `initState` 创建，`dispose` 释放）
- `_inputField` 方法改为接收已有 controller，不再每次新建
- 仅在外部配置加载时同步 controller 文本（用 `_syncIf` 模式）

#### 2. 修复测速（speed_test.dart）
- `testSingle` 中 `requestUrl` 改为 `'$scheme://$ip:$port${uri.path}${uri.query.isNotEmpty ? "?${uri.query}" : ""}'`
- `Host` 头保持为源站域名（`hostname`）
- 给 `_Semaphore` 加 `cancel()` 方法（与 `latency_prober.dart` 的实现对齐）

#### 3. 结果表加滚动条（results_table.dart）
- 在 `ListView.builder` 外包裹 `Scrollbar` widget，提供可见滚动条

#### 4. 丰富结果信息（result_state.dart + results_table.dart）
- `ResultRow` 增加 `jitter` 字段
- `ResultNotifier.loadFile` 加载同名 `.json` 旁文件，读取 `jitter_ms` 填充到行数据
- `ResultTable` 增加"抖动"列
- `ResultState` 增加 `filterMaxJitter` 过滤能力
- 结果过滤栏增加抖动过滤滑块
